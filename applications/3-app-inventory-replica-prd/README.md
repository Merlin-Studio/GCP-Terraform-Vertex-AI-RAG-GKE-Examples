## Starting the replication into `inventory-replica-relational-prd`

`inventory-replica-replicate-prd` replicates the on-premises database into `inventory-replica-relational-prd`, the instance this stage creates and the application reads. The apply creates the job without starting it, because Database Migration Service has to demote an existing destination first and Terraform cannot:

1. Apply this stage. `inventory-replica-relational-prd` is created with no database of its own: a destination must be empty, and the source's databases arrive with the replica. Its version must be the source's or newer.
2. `deploy/replicate-inventory-replica-replicate-prd.sh demote --confirm` checks that and demotes the instance. From here until promotion it is a read replica of the source: the application can read it, and nothing can write to it.
3. `deploy/replicate-inventory-replica-replicate-prd.sh start` verifies the job and starts it.
4. When the cloud copy should take over, promote `inventory-replica-relational-prd`, set `inventory_replica_replicate_prd_replicating = false` and apply this stage again. That turns backups and point-in-time recovery back on; while it replicates the service manages them, and this stage leaves them off so an apply does not undo that.
