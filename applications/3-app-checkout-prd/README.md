## What Merlin did not produce

This stage is the platform an application lands on, not the application. You still own:

- **internet**: dns records, certificate ownership, firewall rule content
- **api**: application code, routes and handlers, runtime configuration
- **relational**: schema and migrations, extra users and engine flags
- **events**: message schema, message contents
- **stream-processing**: pipeline code, transforms and windowing, schema mapping
- **warehouse**: schema and tables, views and queries

The container image is a placeholder until your pipeline publishes one, and the database secret is an empty container: the value is added out of band, so it never passes through a specification, a bundle or a state file.

## What costs money from the first apply

A streaming pipeline starts when this stage is applied and runs until it is stopped. Its workers are billed while they run, whether or not any message arrives, so this line on the bill begins before the application has a single user. That is deliberate -- a pipeline that waits for someone to start it is a backlog nobody noticed -- but it is a decision, so here it is.

| Pipeline | Workers | Machine | Runs |
|---|---|---|---|
| `checkout-stream-processing-prd` | at least 1, up to 4 | `n1-standard-2` | continuously, from apply |

To hold the cost until the application is live, apply this stage without the pipeline (`-target` the rest) or drain the job after the first apply; the budget in `operations.tf` warns at half, most and all of its amount.

## Before you apply

Run `deploy/preflight-checkout-prd.sh` first. In your own environment it checks that:

- the projects exist
- the VPC, subnet and Private Service Access range exist in the Shared VPC host
- each project is attached to that host
- every landing-zone key this stage names exists where the landing zone keeps it
- every firewall policy a front door attaches exists in its project
- the services the stage uses are enabled

and names the assumption and the resource when one does not hold. What it cannot see from outside -- that your deploying identity may use every one of these -- `terraform plan` finds next.
