# Deployment guide — workload stages

These stages sit on top of the landing zone generated for Cloud Foundation Fabric `v58.0.0`. Apply the landing-zone stages first, in order: `0-org-setup`, `1-vpcsc` (if present), `2-networking`, `2-security`, `2-project-factory`.

## The short way

`deploy/` carries the whole sequence: the stages in the order they must
run, each as the identity the landing zone provisioned for it.

```bash
./deploy/verify.sh /path/to/fabric-checkout      # refuses the wrong landing zone
./deploy/apply.sh  /path/to/fabric-checkout --plan-only
./deploy/apply.sh  /path/to/fabric-checkout
```

`deploy/RUNBOOK.md` explains the order and what to do on a re-run;
`deploy/Jenkinsfile.example` is the same sequence for a pipeline. The
rest of this guide is what those scripts do, stage by stage.

## Prerequisites

- The Fabric checkout used for the landing zone (`git checkout v58.0.0`).
- The tfvars published by the landing-zone stages in the `iac-outputs` bucket
  (`0-org-setup.auto.tfvars.json`, `2-networking.auto.tfvars.json`,
  `2-security.auto.tfvars.json`), fetched with `fast-links.sh`.
- The provider/backend file each `3-*` stage needs. The landing zone lists
  these stages in `output_files.providers`, so 0-org-setup publishes one per
  stage alongside the others; fetch them the same way.
