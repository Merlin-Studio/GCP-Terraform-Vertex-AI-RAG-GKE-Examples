# 3-delivery-pools

The Cloud Build private pools every application's Cloud Deploy targets run on.

| Pool | Network | Used by environments |
|---|---|---|
| `deploy-vpc-shared-dev` | `vpc-shared-dev` | `dev`, `stg` |
| `deploy-vpc-shared-prod` | `vpc-shared-prod` | `prd` |

## Why a private pool

Cloud Deploy renders and deploys in Cloud Build. Inside a VPC Service Controls
perimeter it must use a private pool, not the default one, and the pool's
project must be in the same perimeter as the Cloud Deploy resources -- both are
`app-core-0` here.

## Why one shared stage

A project holds at most ten private pools per region, and every application's
delivery stage lives in `app-core-0`. A pool per application would stop
at the eleventh. One pool per workload network serves every application.

## What it assumes

Each pool is peered to its network through the Private Service Access
connection `2-networking` makes on every workload VPC. Run
`deploy/preflight-delivery-pools.sh` first: it checks each connection exists.
Workers are `e2-standard-2` with 100 GB disks and no external
address. The machine size is Merlin's opinion: a deploy renders manifests and
calls APIs, and compiles nothing.

Apply this stage before any `3-app-*-delivery` stage; the targets name these pools.
