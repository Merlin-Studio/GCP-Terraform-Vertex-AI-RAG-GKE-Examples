> This guide walks you through deploying the generated configuration files step by step,

## Overview

Your configuration was generated as **FAST factory YAML data files** — structured
datasets that plug directly into Google Cloud's
[Cloud Foundation Fabric (FAST)](https://github.com/GoogleCloudPlatform/cloud-foundation-fabric/tree/master/fast)
landing zone framework.

FAST handles all Terraform module code for you. Your job is to **place the
generated data files into the correct FAST stage directories** and run
`terraform apply` stage by stage.

## 4. Stage-by-Stage Deployment

FAST stages must be deployed **in order** because each stage produces output
files consumed by subsequent stages.



### Stage 1: Organization Setup (`org-setup/` → `fast/stages/0-org-setup/`)

Folders, IAM bindings, org policies, tags, billing, automation project.

**Copy generated data files** (the stage reads `datasets/classic` by default):

```bash
# From your extracted zip directory, inside the Fabric checkout:
cp -r org-setup/* fast/stages/0-org-setup/
```

**Deploy:**

```bash
cd fast/stages/0-org-setup
terraform init
terraform plan -out=tfplan
# Review the plan carefully, then apply:
terraform apply tfplan
cd ../../..
```


> **Important:** stage 0 creates the state buckets and the stage service accounts, and
> writes the provider/backend files for every later stage into the `iac-outputs` bucket
> (see `output_files.providers` in `defaults.yaml`). Fetch them with FAST's
> `fast-links.sh` helper before running the next stage, as documented in the
> [0-org-setup README](https://github.com/GoogleCloudPlatform/cloud-foundation-fabric/tree/v58.0.0/fast/stages/0-org-setup).
> Before applying, replace any placeholder in `global:` (organization id, billing account).

## 5. Understanding $-Interpolation Tokens

The generated YAML files contain special tokens that FAST resolves automatically
at `terraform plan` time:

| Token | Purpose | Example |
|-------|---------|---------|
| `$iam_principals:...` | References IAM identities from the FAST registry | `$iam_principals:group:admins@vendora.eu` |
| `$project_ids:...` | References project IDs created by earlier stages | `$project_ids:sec-core-0` |
| `$folder_ids:...` | References folder IDs from the resource hierarchy | `$folder_ids:teams/production` |

These tokens ensure **cross-stage dependencies are resolved automatically** — you
do not need to manually copy IDs between stages.

## 6. State Management

FAST manages Terraform state in GCS buckets created during the bootstrap stage:

- Each stage stores its state in a separate GCS prefix
- The bootstrap stage creates the state bucket and configures backend settings
- Output files from each stage (typically in `fast/stages/<stage>/data/`) feed into
  the next stage as input
- **Never delete the state bucket** — it contains the source of truth for all
  deployed resources

## 8. Common Issues

| Issue | Cause | Fix |
|-------|-------|-----|
| `Error: Provider configuration not present` | Missing backend/provider files from previous stage | Copy output files from the prior stage into the current stage's `data/` directory |
| `Error: Insufficient permissions` | Service account lacks required IAM roles | Ensure the bootstrap SA has Organization Admin and Billing Admin |
| `$project_ids:... not found` | Referencing a project from a stage that hasn't been applied yet | Deploy stages in order (0 → 1 → 2 → ...) |
| `Error: Resource already exists` | Re-running a stage that was partially applied | Run `terraform import` for the existing resource, or remove it manually |
| Org policy conflicts | Pre-existing org policies conflict with generated ones | Review existing policies with `gcloud org-policies list` and resolve conflicts before applying |
